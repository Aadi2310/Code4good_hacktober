# P3 implementation decisions

## Scope and repository state

The upstream repository currently contains the README, assets, and animation script only. The documented `backend/vyom/models.py`, P1/P2 modules, dependency aggregator, and project test configuration are absent. P3 code follows the frozen contract documented in `VYOM_P3_Validation_Extraction_VLM.docx`; shared schemas were not recreated or changed. The extraction builder imports P1's contract models at the point they are needed, so the full record pipeline requires P1 to add the agreed models.

## Implemented scope

P3 supplies standard-library-only normalizers, GSTIN checksum and generation helpers, JSON-compatible reference tables (including JSON syntax in the YAML rate file), deterministic validation, confidence combination, merge, grounding, an optional OpenAI-compatible VLM, and a no-model fallback. The P3 requirement file adds no packages. There is no local Transformers provider; it remains optional and untested.

GST rate metadata follows the supplied project specification and records CBIC's 2025 rate notification as the source checked on 2026-10-10. This reference provides known-rate checks and a regime-change warning only; it does not determine the legally applicable rate for a product. [CBIC Integrated Tax (Rate) Notification No. 9/2025](https://courier.cbic.gov.in/ECCS/advisory/2025/NOTIFICATION%20NO.%209_2025-INTEGRATED%20TAX%20%28RATE%29%20-1759486719.pdf)

## Known gaps

- The missing shared Pydantic models and missing P2 extractor prevent end-to-end integration in this checkout.
- The initial implementation includes GSTIN repair and amount-in-words parsing/repair. General equation-derived repair, invoice-level sums for every tax component, line-row alignment across different row orders, table-band splitting, response-schema guided decoding, JSON repair/re-prompt, and the local Transformers provider are deferred. QR disagreements are surfaced as `QR_MISMATCH`; choosing the QR value does not suppress the conflict check.
- The validation engine accepts the contract shape and reports core GSTIN, key-field, taxable-sum, total, and tax-type checks. It is not legal tax advice and cannot assert a rate is applicable to an HSN.
- The reference dataset is the required project subset, not an exhaustive GST rate schedule.
- Amount words use a small built-in vocabulary and standard-library fuzzy matching instead of the excluded `rapidfuzz` dependency.
